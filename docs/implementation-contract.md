# Relay — first implementation contract

Working title: Relay. This is a durable first foundation for the multi-month product described in vision.md. Build an original local workspace with real persistence and supported provider harnesses. Do not claim distributed coordination, automatic integration, or advanced orchestration is complete.

## Stack

pnpm workspace; React 19 + TypeScript + Vite; Tailwind or plain CSS with design tokens; TanStack Router and Zustand if useful; Node >=24.13; WebSockets; SQLite via node:sqlite; node-pty; Monaco and xterm; Electron desktop entry point. Effect may be used where useful, without copying T3 abstractions. Core architecture matches T3's UI / Node / provider process separation. Rust isn't required to launch the Codex Rust executable.

## Desktop distribution

Relay is intended to be an installed desktop application. Linux x86-64 packaging stages Electron, a checksum-pinned official Node runtime, the compiled backend, production dependencies and built web assets. The installed app manages its loopback server and stores data under the Electron user-data directory, without requiring pnpm, a source checkout or a manually started server. Provider CLIs and their logins remain separately installed.

`pnpm package:linux` produces the standalone archive; `pnpm package:arch` adds an installable `.pkg.tar.zst` and checksum using `makepkg` as an ordinary user. The Arch recipe installs a launcher, icon and properly owned sandbox helper. Package creation does not install into the host or publish a release. AUR/GitHub Release publication requires the owner's approval; there is no AUR entry or automatic updater yet. See desktop-distribution.md for the exact build/publication contract and outstanding release prerequisites.

## HTTP and WebSocket contract

All HTTP routes use /api. Errors: {error: string}. JSON success bodies, except file content endpoint. API server port 4310 on 127.0.0.1, Vite port 5173. Vite proxies /api and /ws. Production server serves apps/web/dist. Default data directory is .relay under repository root (override RELAY_DATA_DIR); never tracked.

- GET /api/bootstrap -> Bootstrap (shared contracts), includes durable messages, events, run records and structured tool calls. Runs retain start/end times and monotonic elapsed duration; tool lifecycle updates reuse a stable provider ID per run. Bootstrap prioritizes active runs and bounds recent run/tool records, with tool output tails capped at 2,000 characters. GET /api/runs/:id/tools loads up to 1,000 full bounded records; GET /api/tool-calls/:id loads one detailed record. Both reject archived sessions. Tool output is bounded at 20,000 characters and exposes outputTruncated when clipped. Initial state creates one clearly labeled example project with a local folder, readme/contract files, tasks and TWO idle sample sessions (not active provider calls). isExample=true. Do not invent metrics or completed runs. Runtime defaults to this example until user opens their own project.
- POST /api/projects {name,path} -> Project. Path must exist; use canonical real path. PATCH /api/projects/:id {name} -> Project changes its display name without moving its folder. GET /api/projects/:id/files?path=relative -> FileEntry[]. GET /api/projects/:id/file?path=relative&sessionId=optional -> {content,path}; PUT same endpoint {content} saves text. Refuse traversal, symlink escapes, .git and secrets. Files can be scoped to a session worktree.
- POST /api/sessions CreateSession -> Session. Only projectId is required; omitted name/provider/model/effort/policy/isolation resolve from application defaults, with an automatic session name. Git projects isolated by default using unique worktree+branch under data directory. Clear errors for nonrepo/unborn HEAD. Nonisolated sessions explicitly opt in. PATCH /api/sessions/:id {name?,provider?,model?,effort?,policy?,pinned?,unread?} -> Session. Pin/unread flags persist independently of conversation activity and do not change updatedAt. Metadata-only flag changes broadcast state without adding activity events. Run settings reject changes during an active run or cleanup; a provider change rejects after a provider conversation exists, while model/effort changes preserve that conversation. DELETE /api/sessions/:id archives metadata but never removes worktrees. POST /api/sessions/:id/messages SendMessage -> {accepted:true}; starts asynchronous provider run. 409 if active. POST /api/sessions/:id/interrupt -> {ok:true} cancels process, denies pending approvals.
- GET /api/projects/:id/git?sessionId=optional -> GitStatus. Read-only status and diff. No push/merge endpoint in this foundation.
- POST /api/tasks CreateTask -> Task. PATCH /api/tasks/:id UpdateTask -> Task; reject cycles, cross-project deps or ownership, invalid transitions past unfinished deps. Mark downstream ready when dependencies done. POST /api/tasks/:id/run -> {accepted:true}; dispatch assigned session with task context, moves to review on successful turn, never auto-done.
- POST /api/handoffs Handoff -> WorkspaceEvent. Verify source/target same project, artifact committed at revision in source repo; create compact reference and durable receiving system message. Does not silently merge or start a paid model run. Include artifact content or source path reference for consumption; downstream session should receive it with next explicit run.
- POST /api/approvals/:id {decision:'approved'|'denied'} -> Approval. Approvals belong only to active local run; expire/deny on restart and interruption.
- PATCH /api/settings UpdateSettings -> AppSettings. No credential UI or secret storage; Claude uses its existing local CLI login or an explicit ANTHROPIC_API_KEY in the server environment. Executable paths may be configured. GET /api/providers -> ProviderInfo[]. POST /api/providers/refresh -> ProviderInfo[]. Accurate diagnostics; codex --version and Claude executable selection/auth-status probes with timeout. Installed != authenticated; do not claim authentication based on executable alone.
- GET /api/events?after=integer&projectId=optional -> WorkspaceEvent[] for replay.
- WS /ws -> ServerEvent. Connected client receives state.changed on mutation. Client re-fetches bootstrap (debounced), session.delta updates live text at its absolute offset to handle snapshot overlap. Terminal messages use shared ClientEvent with {type:'terminal.ready',terminalId} server handshake and {type:'terminal.error',message} for failed starts. PTY owner socket only, project/session cwd validation, kill on disconnect. No shell interpolation.

## Provider module contract

apps/server/src/providers/index.ts exports createAdapter(provider: Provider): AgentAdapter and detectProviders(settings: AppSettings): Promise<ProviderInfo[]>; interface types in @relay/contracts. Provider agent owns only this subtree + provider tests and docs/provider-research.md.

Codex: launch codex app-server over stdio; JSON-RPC initialize/initialized; thread/start or thread/resume; turn/start; deltas and tool records; forward approval requests to host callback; interrupt/abort; process timeout and cleanup; restore provider session id. No OAuth extraction. Use existing CLI login.

Claude: use official @anthropic-ai/claude-agent-sdk query(), resume provider session id, stream partial text, map canUseTool to requestApproval, support AbortSignal. For this local workspace, let Claude Code use the local user's existing login; an explicit API key takes precedence. Probe login status through `claude auth status --json`, never by reading credentials. Do not implement an OAuth broker, token extraction or browser credential storage. Honor model and effort. No automatic fallback model substitutions. See provider-research.md for the dated authentication sources and hosted-product scope.

## Run and tool activity

Provider adapters emit `tool.activity` lifecycle snapshots keyed by the provider invocation ID and `tool.output` deltas. A start/result pair updates one invocation and counts once. Only real provider parent IDs produce nested calls; shell command strings are not parsed to invent process trees. Provider-reported command, working directory, process ID, exit code, result and timing are retained when available. Text is redacted before persistence/transport using the existing best-effort credential scrubber.

The runtime persists run records and message/run links with additive schema migration 3. Run elapsed duration uses a monotonic host clock during normal completion/interruption. Recovery marks unfinished runs/tools interrupted without fabricating an elapsed duration across server downtime. Old text-only history is retained without guessed identities, timings or subprocesses.

Migration 5 adds a saved change summary and bounded patch to each run. Before invoking the provider, Relay captures eligible tracked/untracked working files into local Git objects; after the provider stops, it compares the two trees. This includes staged, unstaged and committed edits without modifying the real index, refs, working files or creating commits. Ignored untracked and denied secret paths are excluded, and no clean filters, external diff helpers or textconv commands run. The result describes net workspace changes, including concurrent edits by other writers. Nonisolated sessions include a shared-folder notice.

`SessionRun.changes` carries the summary in bootstrap; `GET /api/runs/:id/changes` loads the saved patch on demand. The endpoint rejects active runs and archived/missing sessions, and reports historical runs without snapshots as unavailable rather than reconstructing their edits. The UI places one card after each finished run's final assistant message, with compressed folder groups, aggregate/per-file counts, binary indicators and a read-only diff dialog. Empty known snapshots are hidden.

Capture is bounded to 2,000 eligible files, 10 MiB per file, 100 MiB total and a checked 15-second budget (individual Git operations also have timeouts). Incomplete/unreadable/unstable snapshots or unsupported submodules make the summary unavailable, preserving provider execution. Summary lists cap at 200 files with complete overall totals; saved patches cap at 500 KiB, and the viewer limits each file to 1,500 rendered lines with a notice. Renames are represented as deletion/addition. Capture baselines live in memory, so interrupted runs recovered after a server crash have no reconstructed summary. Completed summaries and patches remain in SQLite. Git objects written for checkpoints are unreferenced and follow the repository's normal garbage collection.

## Provider controls and command discovery

Additive migration 4 stores `sessions.service_tier`, defaulting existing sessions to `standard`. CreateSession, UpdateSession and settings accept a service tier. Provider model metadata carries supported reasoning identifiers, model aliases, speed tiers, reported defaults and model-specific permission modes. Session creation/model changes normalize inherited defaults to supported choices; explicit unsupported effort, tier or permission values reject. Active runs and provider cleanup keep configuration locked.

`GET /api/sessions/:id/catalog` returns native commands, skills and bounded discovery notices, cached briefly; `?refresh=true` requests a refresh. Discovery uses Codex `skills/list` or Claude SDK initialization/control methods with an open prompt stream that yields no messages. It starts no inference. `POST /api/sessions/:id/messages` also accepts optional `skills: string[]`; IDs are resolved against a fresh server-side catalog and session identity is checked again before starting the run. Arbitrary client-supplied skill paths are never trusted. Claude accepts one explicit skill selection per message.

`GET /api/sessions/:id/usage` returns `SessionUsage`: native provider quota windows, optional credit/reset details, bounded notices, fetch time and current local conversation totals. `?refresh=true` bypasses the normal 60-second cache after a minimum 15-second cooldown from the previous result. Unavailable snapshots cache for 15 seconds; concurrent reads coalesce. Snapshots stay in bounded process memory. The route rechecks session existence and provider/model identity after asynchronous discovery. Codex reads `account/rateLimits/read`; Claude uses its experimental SDK usage control with transcript scanning skipped. Both have bounded requests and process cleanup without starting inference. `/usage` is a local composer action and remains available during a run. Its dialog shows only reported values; no reset redemption, invented credit denomination, inferred replenishment date or account credential access is implemented.

Codex Auto selects its native approval reviewer; Full access uses the native unrestricted sandbox and no approval prompts. Claude maps to its native `auto` and `bypassPermissions` modes; Auto is shown only for models reporting support. Codex Standard explicitly sends `serviceTierForTurn: 'default'`; Claude speed maps to the SDK flag-settings `fastMode`, with runtime availability failures surfaced. Existing CLI authentication remains provider-owned. See provider-feature-parity.md and the dated provider controls research documents for exact mappings and limitations.

## UI direction

Minimal desktop workspace, responsive down to 900px (smaller widths graceful overlay). Neutral black/charcoal surfaces, white emphasis and rare blue accents; no purple. Sidebar contains project/session selection, search and compact creation actions; secondary task/activity/map views are under the footer's More menu. Conversation is primary; context pane and terminal start closed and can be opened on demand. User messages use right-aligned soft bubbles; assistant messages are plain prose without provider icons or repeated model headers. Composer has editable model, effort and approval controls using shared polished choice popovers. New Session creates directly without a popup, using stored provider/model/effort/workspace defaults. Settings is a full page with General, Project, Providers and Appearance categories, not a drawer. Session rows offer a grouped context menu via right-click, Shift+F10 or a three-dot button. It supports pin/unpin, rename, manual read/unread flags, copy details, project settings and confirmed archival. Pinned sessions appear first; opening a session explicitly clears its unread flag. Project settings edits the display name and shows the canonical folder path; new-session defaults remain global. Keep truthful example identification, accessible controls and visible failures. Preserve file editing, diffs, tasks, handoffs and real terminal functionality. A compact activity disclosure appears per run, with a live elapsed timer, authoritative tool/category counts and a final duration. Expanding reveals structured tool details and supported child calls; full bounded output loads on demand. Legacy adjacent tool messages group as output records, with descriptive command previews and no invented invocation count. See ui-direction.md for references and the current revision. Original code, no T3 source copy.

Workers must commit their own scoped changes, with no coauthor trailers, and never push. Orchestrator owns root packages/config/contracts/docs except provider-research.md. Workers may create their app package.json. Coordinate dependency additions in final report; root owns shared lockfile.
